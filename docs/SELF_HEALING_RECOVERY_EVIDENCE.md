# Self-healing recovery evidence

Every number on this page is recomputed from timestamps stored by the system
itself (chaos experiment journal, Healer attempts, Docker `StartedAt`) by
`scripts/final/evidence-report.mjs` over
[FINAL_MEASUREMENTS.json](FINAL_MEASUREMENTS.json). Nothing is typed in by
hand, and **failed executions are kept**: they are how the defects listed in
[FINAL_SYSTEM_ARCHITECTURE.md](FINAL_SYSTEM_ARCHITECTURE.md) were found.

## Method

- Host: linux 6.18.44-fc-v153, 4 vCPU (Intel(R) Xeon(R) Processor @ 2.10GHz), 16 GiB, Docker 29.9.1.
  Single host, cloud sandbox; numbers are demo evidence, not capacity claims.
- Faults go through the real admin chaos API (CSRF, typed confirmation).
  Repairs are made **only** by the independent Healer; a scenario is COMPLETED
  only with an accepted Docker receipt **and** independent functional verification.
- Video is decoded with ffprobe from the public HLS path (web → video gateway →
  edge) by `scripts/final/hls-viewer.mjs`, labelled "ffprobe-decoded" — this
  sandbox's Chromium has no H.264 (see [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md)).
- Chat is measured over Socket.IO pinned to API-1 and API-2; latency from real
  requests through the web origin.
- Column meanings: **Detect** = injected → incident detected; **Act** = injected →
  Healer action started; **Action time** = action started → receipt; **Restore** =
  injected → independent verification. For the surge, Restore runs to the
  scale-out verification and the experiment additionally waits for scale-in.

  threshold only after the load ended (PARTIAL).

  was not run here: each round spends most repair budgets, so a second round
