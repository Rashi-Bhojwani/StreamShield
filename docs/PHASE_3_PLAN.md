# Phase 3 implementation plan

PR #3 is open. Start from verified remote Phase 2 head 89983b7; deliver feature/phase-3-streaming-platform as a stacked PR targeting feature/phase-2-live-streaming. Preserve all work; no force push, cherry-pick or automatic merge. After #3 merges, merge current main normally into this branch and retarget to main.

1. PostgreSQL 17 with pg and node-pg-migrate: UUID users/channels/streams, unique normalized accounts/slugs/media paths, foreign keys, UTC timestamps, hashed revocable sessions, hashed per-stream publish keys and durable ordered chat. Explicit one-shot migrations; no destructive startup resets; persistent named volume and isolated test database.
2. Argon2id passwords, opaque HttpOnly SameSite cookies, server-side expiry/revocation. Exact Origin and nonce-bound HMAC CSRF tokens protect writes including login/logout. Redis limits sensitive actions and fails closed. Registration cannot choose roles; owned channel creation transactionally grants broadcaster capability. Admin provisioning requires trusted local DB access.
3. Dedicated private MediaMTX HTTP auth listener with service Basic authentication; no forwarded-header trust. Verify path/state/individual publish-key hash. Rotation/end revoke first and kick active path publishers via private Control API. Keep the Phase 2 credential only for its explicitly scoped development compatibility path; prohibit it in production. Public HLS stays independent of DB/Redis for ongoing playback.
4. Stream draft/ready/ended lifecycle is distinct from verified starting/live/offline/unknown media status. Actual observations update start/end metadata, never the reverse. Bounded DB discovery and channel search replace the single-stream catalog limitation.
5. Socket.IO with supported Redis adapter, separate pub/sub clients, authenticated CSRF-bound handshakes and per-message session validation. Stream-specific rooms; parameterized durable PostgreSQL messages, ordered cursor history, bounded input/rate limits, reconnect catch-up and honest errors.
6. Redis expiring presence leases count distinct active account sessions or anonymous browser identity per stream, deduplicating tabs. Actual advancing-player heartbeats stop on pause/hidden/unmount. Disconnect removes leases; TTL handles crashes. Public counts are approximate active players, never personal identifiers or capacity claims.
7. Keep full-width Live UI and media player. Add real signup/login/profile/account navigation, public channel pages and protected Studio for owned channel/stream creation/edit/history, live preview, masked one-time keys, rotation/end and OBS instructions. Real chat respects manual scrollback and exposes connection/degraded states.
8. Validated DB/Redis addresses, credentials, pool/deadline limits, sessions/cookies/CSRF, rate limits, socket/presence and private media-auth settings. setup:platform preserves existing .env and generates secrets without displaying them. Docker exposes only existing local app/media ports. Windows uses npm.cmd, Docker Desktop and normal registration.
9. Preserve Phase 1/2 checks and real decoding. Add isolated real DB/auth/ownership/key/chat/presence tests, two independent publishers/viewers, persistence restart and Redis-degradation checks, and browser account/Studio/channel/chat flows. Inspect real screenshots at 375/768/1280/1440/1920. Document actual results and every unverified limitation.
10. Research official MediaMTX HTTP auth/control API, PostgreSQL/pg/migrations, Redis/Socket.IO adapter, Argon2id and cookie/CSRF guidance. Pin maintained dependencies. Existing React Query, shared Zod, logging, deadlines and API conventions remain.

Redis Pub/Sub is not durable; PostgreSQL owns history. Dependency outages must not tear down already playing HLS. Rotation/end explicitly reports failure if a revoked active publisher cannot be kicked. No password reset/email verification, upload pipeline, moderation dashboard, replicas, video edges, standby origins, healing or chaos. Local RTMP/HTTP needs HTTPS/RTMPS and deployment hardening before public hosting. Future replicas can share DB, sessions, rate limits, adapter and leases; 50,000–60,000 viewers remains an untested future goal.
